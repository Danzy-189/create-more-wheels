# small-semi-truck_tire

`semi-truck_tire` one size down: the identical mesh written out at 82.6% scale, for rigs
that want a smaller steer wheel from the same visual family.

## Files

| file | how it gets here |
| --- | --- |
| `block.obj` | binary, uploaded through the GitHub web UI |
| `block.mtl` | text |
| `item.json` | text |
| `../../../../textures/block/small-semi-truck_tire/tire_0.png` | binary, uploaded through the GitHub web UI |

`block.obj` and `tire_0.png` cannot go through the contents API, which takes a UTF-8
string, so they are uploaded separately from the text files.

## Geometry

Generated by the `semi-truck_tire` script with one constant changed: the target radius
drops from 0.896 to 0.7399 blocks. The design space is 16 px with the axle on +Z; the
writer scales by 1.51, then rotates -90 degrees about X so the axle ends up on +Y and
the mesh is centred on the block. Nothing else differs, so the two wheels can never
drift apart in shape.

- 762 faces, 2936 vertices, quads only
- mesh radius 0.7399 blocks against a registered radius of 0.8, a 7.5% margin
- bounds 1.4798 x 0.5191 x 1.4798 blocks

Registered at 0.8 rather than Offroad's 0.75 `small_tire`, following
`soviet_small_wheel`, which already sits slightly above that tier.

## Texture

One 32x32 atlas, `tire_0.png`: tread rubber, chrome, dark recess and machined steel in
the four 16x16 quadrants. `item.json` sets `flip_v: true`, so the OBJ stores v
bottom-up.

## Checks

The generator refuses to write a face with more than four corners. The NeoForge OBJ
loader assembles quads and silently drops anything wider, which shows up in game as a
hole rather than as an error, so this is checked rather than assumed. A render pass then
confirms zero see-through pixels from six camera angles, front and back, and that every
primitive is closed and consistently wound.
